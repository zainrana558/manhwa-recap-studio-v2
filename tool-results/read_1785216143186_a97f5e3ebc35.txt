     1→# Master Recap Pipeline — Work Log
     2→
     3→## Project Overview
     4→Build a Next.js web app that:
     5→1. Lets user enter a manhwa/manga/webtoon **name** (not URL)
     6→2. Searches MangaDex (free official API) for the title
     7→3. Scrapes **every chapter** (hundreds if needed) — all panel images
     8→4. Generates per-chapter summaries using VLM (z-ai-web-dev-sdk)
     9→5. Translates non-English content to English using Groq (OpenAI-compatible)
    10→6. Runs the uploaded Python `master_pipeline.py` to produce a narrated recap video with captions + BGM
    11→7. Streams real-time progress via WebSocket; user previews/downloads the final MP4
    12→
    13→## Architecture
    14→- **Next.js app (port 3000)**: UI + REST API routes (search, manga, jobs, settings, download)
    15→- **Pipeline mini-service (port 3001)**: socket.io server that scrapes MangaDex, generates VLM summaries, calls Groq for translation, runs the Python pipeline as a subprocess, streams progress
    16→- **Prisma/SQLite**: Job, Chapter, Setting models
    17→- **MangaDex API** (https://api.mangadex.org): free, no auth, multi-language
    18→- **z-ai-web-dev-sdk**: VLM for chapter summaries (backend only)
    19→- **Groq**: translation (OpenAI-compatible endpoint)
    20→
    21→## Key decisions
    22→- Keep Python pipeline as subprocess (it works, has ffmpeg/whisper/moviepy installed)
    23→- Adapt pipeline so Groq can be used for BOTH translation and narration rewrite (user only needs Groq key)
    24→- VLM generates `summary.txt` per chapter from scraped images before running the Python pipeline
    25→- Limit chapters by default (configurable) so demos don't take hours
    26→- WebSocket on port 3001, path `/`, frontend connects via `io("/?XTransformPort=3001")`

    93→  - `processJob(jobId)` core pipeline:
    94→    1. SCRAPE: sets status=scraping. If no Chapter rows exist (API didn't pre-create), fetches via MangaDex and creates them. For each chapter: fetchChapterPages → downloadMangadexImage with 300ms rate-limit delay → save as `{NNN}.{ext}` → update Chapter.pageCount/status=scraped → emit chapter + progress (5-30% range based on doneImages/totalImages). Skips already-downloaded files (resumable). Failed chapters marked error but don't kill the job.
    95→    2. SUMMARIZE: sets status=summarizing. For each scraped chapter: list images, call generateChapterSummary, write summary.txt, update Chapter.status=summarized/summarized=true. Emits progress 30-45%.
    96→    3. RENDER: sets status=rendering. Spawns `python3 master_pipeline.py` with --input-dir/--output/--work-dir/--voice/--narration-provider auto/--skip-captions/--progress-file/--keep-temp, plus --groq-api-key/--openai-api-key/--no-translate conditionally. Streams stdout/stderr line-by-line as JobLog entries. Polls progress.json every 1s; maps stage render→45-95%, merge→95%, bgm→97%, done→100%. On exit code 0: status=done, outputVideo=master_recap.mp4, emit done. On non-zero: status=error, emit error.
    97→  - Cancel: adds jobId to cancelledJobs set, SIGTERM the child process (SIGKILL after 3s if still alive), updates DB status=cancelled, emits cancelled event. processJob checks cancelledJobs at every loop iteration and bails out.
    98→  - Graceful shutdown: on SIGTERM/SIGINT, kills any running subprocess, closes io + httpServer, force-exits after 5s.
